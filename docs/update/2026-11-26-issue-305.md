# [API 버그] /auth/refresh 보안 취약점 수정 (#305)

## 변경 이유

`POST /auth/refresh` 에서 두 가지 보안 취약점이 발견되었습니다.

1. **로그아웃한 기기의 refresh 토큰으로 갱신 가능**: `AuthService.logout`은 refresh 토큰을 블랙리스트에 등록하지만, `validateAndExtractUserId`는 블랙리스트를 확인하지 않아 로그아웃 후에도 새 토큰을 발급받을 수 있었습니다.

2. **탈퇴 유예 중인 계정의 다른 기기가 갱신 가능**: `deactivateUser`는 현재 요청의 access 토큰만 블랙리스트에 등록하고, 다른 기기의 refresh 토큰은 그대로 유효한 상태로 남아 세션이 계속 유지되었습니다.

## 변경 내용

**`AuthService.java`**

- `validateAndExtractUserId`: refresh 토큰이 블랙리스트에 있으면 `INVALID_REFRESH_TOKEN` (A0009/401)으로 거절 (로그아웃된 기기 차단)
- `refreshToken`: 사용자 조회 후 `UserStatus.DELETED` 상태이면 `USER_NOT_FOUND` (U0002/401)으로 거절 (탈퇴 유예 중 계정의 다른 기기 차단 — 안 A 선택)
  - 거절 시 앱이 세션 종료로 인식하는 코드(`A0009`, `U0002`)를 사용하여 로그인 화면으로 이동
  - 같은 계정으로 재로그인 시 기존 탈퇴 취소 흐름(`handleUserStatus`) 그대로 동작
