# Issue #11 – Initial App Communication (App Version Check)

## Summary

The app version check feature was already implemented as part of the bootstrap infrastructure.
This entry documents where the implementation lives.

## Implementation

| File | Description |
|------|-------------|
| `entity/AppVersion.java` | JPA entity: osName, minVersion, nowVersion, needForceUpdate, updatedAt |
| `repository/AppVersionRepository.java` | `findByOsName(osName)` lookup |
| `service/AppVersionService.java` | `checkAppVersion(request)` — compares current app version against min/now versions; returns force-update flag |
| `dto/AppVersionResponse.java` | Public DTO: minVersion, nowVersion, needForceUpdate |
| `dto/BootStrapRequest.java` | Request DTO: osName (ANDROID / IOS) |
| `controller/BootStrapController.java` | `GET /bootstrap/info?osName=ANDROID` — returns version info + active notice |

## Admin API

Admins manage version records via `AdminAppVersionController` at `/admin/app-versions`.

## Bootstrap Response Example

```json
{
  "appVersionInfo": {
    "minVersion": "1.2.0",
    "nowVersion": "1.5.0",
    "needForceUpdate": false
  },
  "notice": null
}
```

`needForceUpdate: true` signals the client to block usage until the user updates.
`minVersion` can be used for optional-update prompts when the installed version is below `nowVersion`.
