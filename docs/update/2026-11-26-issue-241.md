# #241 탈퇴 30일 영구 삭제 DB 제약 실패 확인 및 보완

## 문제
`ddl-auto: update`는 기존 FK의 `ON DELETE` 동작을 바꾸지 않는다.
`@OnDelete(CASCADE/SET_NULL)` 어노테이션이 추가된 시점(2024-10-10, 커밋 5d7a675) 이전에
만들어진 테이블은 실제 DB에 `ON DELETE` 제약이 없어 `userRepository.delete(user)` 시 FK 위반으로 실패한다.

## 코드 변경

**`UserCleanupService.java`**
- `deleteUser()` 에서 `userRepository.delete(user)` 직전에 `userNoticeSettingRepository.delete(noticeSetting)` 명시적 삭제 추가
- `user_notice_setting.user_id` FK 가 DB에 `ON DELETE CASCADE` 없이 남아 있어도 삭제 성공하도록 보완
- (가입 때 모든 회원에게 `UserNoticeSetting`이 생성되므로 이 FK가 가장 먼저 막힘)

## DB 직접 적용 필요 (dev · prod)
`docs/db/migration-241-on-delete-constraints.sql` 참고.

다음 FK를 직접 `DROP → ADD`해 `ON DELETE` 동작을 명시해야 한다:
- `user_notice_setting.user_id` → CASCADE
- `user_block.blocker_id`, `user_block.blocked_id` → CASCADE
- `BaseEntity` 상속 테이블의 `created_by`, `updated_by` → SET NULL

## 확인 쿼리 (dev DB에서 실행)
```sql
-- users를 가리키는 FK와 현재 ON DELETE 동작 확인
SELECT TABLE_NAME, COLUMN_NAME, CONSTRAINT_NAME, DELETE_RULE
FROM information_schema.REFERENTIAL_CONSTRAINTS rc
JOIN information_schema.KEY_COLUMN_USAGE kcu
  ON rc.CONSTRAINT_NAME = kcu.CONSTRAINT_NAME
  AND rc.CONSTRAINT_SCHEMA = kcu.TABLE_SCHEMA
WHERE kcu.REFERENCED_TABLE_NAME = 'users'
  AND rc.CONSTRAINT_SCHEMA = DATABASE();

-- 30일 경과 DELETED 회원 잔존 여부 확인
SELECT id, deleted_at FROM users WHERE status = 'DELETED' AND deleted_at < NOW() - INTERVAL 30 DAY;
```
